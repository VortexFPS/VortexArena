# Automatic Welcome at native sign-on

At data pin `863cd3e8456e18f577f7fe5fef857ff55ae62cc0`, score initialization sends Welcome data to the joining recipient (`qcsrc/server/scores.qc:229`, `qcsrc/server/client.qc:1077–1132`). CSQC builds the ordinary message and waits for menu readiness (`qcsrc/client/main.qc:1455–1487`). During intermission, demos, or with `cl_welcome 0` it sends `closemenu Welcome` with the payload to initialize the dialog for later use. With the ordinary gate enabled it opens the dialog. The campaign branch issues its own immediate request at lines 1380–1398. The stock server-info bind comes from `binds-xonotic.cfg:52` and `xonotic-client.cfg:26–32`. The earlier [directmenu fixture](directmenu-evidence.md) records the actual stock join on Boil.

Native `HandshakeAccept` carries the briefing text alongside the existing server name, map, and game mode. It is reliable and addressed to the authenticated peer. Native protocol 27 keeps the existing client/server build-parity gate. The server reuses the campaign briefing, active mutators, `g_mutatormsg`, and `sv_motd` sources from the previous per-player chat path. The client uses its mounted map metadata. The handoff passes typed display data to Shell after match state and the owner camera are ready, so server text stays out of the console parser. The loading curtain releases even for a remote spectator who has yet to press Join.

Each sign-on offers the payload once. The client seeds the dialog even when `cl_welcome 0` or intermission suppresses the automatic open. A listen map change creates a new sign-on, and Shell discards the prior cached data on teardown. The connection's own reconnect reset also clears pending data and its match-state latch. Dedicated, observer-capture, benchmark and editor paths skip automatic display. Identity, service and consent policy follow the existing ADR boundaries.

Both Shell constructors configure `NetGame`, register `OnMatchWelcome` through `WireConsoleToNet`, assign `_netGame`, then await the initial paint before adding the node to the tree. The identity check after the await and in the callback rejects superseded matches. A standalone host with a null callback consumes sign-on data without opening UI. Reliable ENet handles retransmissions. The server also ignores auth after acceptance and the client ignores a duplicate accept before re-arming Welcome or restarting the mod session.

The briefing cap is 4,096 UTF-8 bytes. The writer stops at a whole Unicode scalar. The reader discards a complete oversized or malformed field and retains the base map/mode briefing. A field cut short marks the accept packet truncated. The watchdog checks loss immediately after polling, including after spawn. A failed connection returns through Shell teardown before any pending Welcome UI can dispatch. Legacy demo playback uses its own session, so it has no native sign-on producer. The named native route permits Welcome in a demo and disables its Join and Spectate actions.

The frozen audit verifier passed all 176 records and 4,330 lines. The listen fixture logged an audio playback virtual-method error at shutdown after the checks.
