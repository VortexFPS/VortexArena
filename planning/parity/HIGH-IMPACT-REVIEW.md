# High-impact gameplay and server parity review

Audited 2026-11-19 against Xonotic data revision `863cd3e8456e18f577f7fe5fef857ff55ae62cc0` (`v0.8.6-1779-g863cd3e84`). The starting leads come from [PARITY-GAPS](PARITY-GAPS.md).

## Onslaught presentation

- Base bobs the control-point icon during construction and uses the health fraction as model opacity. Once captured, it spins the icon and uses its health updates to trigger a hit punch. The native objective snapshot already carries build state and quantized health. The client now applies those visuals at render rate, including when the snapshot cadence is lower. [Base cl_controlpoint.qc](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/common/gametypes/gametype/onslaught/cl_controlpoint.qc), [ClientEntityView](../../game/net/ClientEntityView.cs), [ClientWorld](../../game/client/ClientWorld.cs)
- The native server sent new model names when a pad changed ownership, a generator took damage or died, or an icon was damaged. The renderer assigned the new name to the proxy but kept the mesh attached at spawn. The client now rebinds Onslaught meshes on a model change. Control-point icons select damage meshes only once captured and restore those meshes on repair. The 75%, 50% and 25% boundaries now follow Base's strict comparisons. [OnslaughtControlPoint](../../src/VortexArena.Common/Gameplay/GameTypes/OnslaughtControlPoint.cs), [Onslaught registry](registry/onslaught.yaml)
- Hit recoil uses decreases in the quantized health byte. Several hits can coalesce between snapshots, and small hits can round away. The recoil uses randomized angles with an approximate distribution. Hit color modulation, the generator event chase camera and the generator destruction effects remain open. [Base cl_controlpoint.qc](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/common/gametypes/gametype/onslaught/cl_controlpoint.qc), [Base cl_generator.qc](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/common/gametypes/gametype/onslaught/cl_generator.qc)

## Map eligibility

The initial lead was confirmed for flag enforcement. The hosted rotation already checked BSP presence and mode support, and both flag cvars were shipped. Concurrent map catalog changes now parse the remaining flags and use separate listing and automatic rotation policies. The mapinfo registry records that implementation and its remaining coverage. [MapInfoBackend](../../src/VortexArena.Common/Menu/MapInfoBackend.cs), [NetGame](../../game/net/NetGame.cs), [MapRotation](../../src/VortexArena.Server/MapRotation.cs), [mapinfo registry](registry/mapinfo.yaml)

- Base's normal filtered catalogs always exclude `forbidden`. The Create Game menu also always excludes `hidden`, while the server can allow it. `g_maplist_allow_frustrating` enables frustrating maps at nonzero values and requires them above 1. [Base common/mapinfo.qc](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/common/mapinfo.qc), [Base menu maplist](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/menu/xonotic/maplist.qc)
- `donotwant` and `noautomaplist` set the same flag. A `gameversion_min` above the local `gameversion` also sets it. The ordinary rotation passes reject that flag, and the explicit compatibility check and repeat fallback can still accept the map. The suggestion command resolves names through the filtered catalog. These paths need separate eligibility checks to reproduce Base's behavior. [Base common/mapinfo.qc](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/common/mapinfo.qc), [Base intermission](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/server/intermission.qc), [Base map voting](https://github.com/xonotic/xonotic-data.pk3dir/blob/863cd3e8456e18f577f7fe5fef857ff55ae62cc0/qcsrc/server/mapvoting.qc)
