# Xonotic and Vortex Arena implementation review

**18 November 2026.** The audit covers all 2,386 registered features across 162 units, every QuakeC source file at the data pin, every upstream data entry outside QuakeC, and every archive member in the two map releases. Source tracing, gameplay tests and rendered checks cover a smaller set. The strongest remaining blind spots are uncited behavior inside source files, engine behavior on real maps, remote-client presentation and combinations of rulesets.

The [scope decisions page](review/index.html) explains seven questions with native screenshots, source evidence and a downloadable prompt for the choices you make. The [ranked discrepancy inventory](PARITY-GAPS.md) includes every scored lead and a separate record of unscored caveats and accepted differences. The [runtime verification queue](NEEDS-INGAME-CHECK.md) identifies observations still needed.

## Reference and method

The native starting point was `43e4b7d91db9267916500e5fbea85414d2d279a6`. The original gameplay and data reference was the project's Xonotic data pin, `863cd3e8456e18f577f7fe5fef857ff55ae62cc0`. For maps, the original comparison used the project's SHA-256-locked repackaging of the Xonotic prebuilt maps, `maps-2026.07`. The native game used its shipped `maps-2026.08` recompile. Runtime checks used Godot 4.6.3 and .NET 8.

The previous ranked report listed 445 rows. Removing its display cutoff and retaining contradictory evidence initially surfaced 626 ranked leads. Of the final 617 ranked leads, 45 score solely because of unknown dimensions. Another 612 zero-score rows retain caveats or mismatched constants. There are 225 rows with a design rationale, including 102 with an open or unknown dimension. A high score identifies work worth inspecting. Before assigning a fix, we traced the original caller, its data and settings, then the corresponding native producer and consumer. We checked architectural decisions and explicit native overrides. This caught historical claims in both directions. The original buff particle helper has no callers, while an implemented Freeze Tag transition was being undone by shared death cleanup.

## Implementation changes and remaining differences

| Area | What changed on a reachable path | What remains |
|---|---|---|
| CTS time trials | Numbered checkpoints enforce order, record splits, and restart a circuit on the same finish crossing. Defrag timers work, bots can target the next touchable gate, and spawnpoint activation no longer starts a run. | Brush contact precision, split delivery to remote HUDs, learned order persistence and penalties. |
| Freeze Tag | A lethal hit leaves the newly frozen player frozen. Frozen hazards respect the configured behavior. Remote overlays, ice pose, chase view, red flash and revive effects consume more of the original state. | Material appearance, spectator behavior and exact local/remote animation timing need paired sessions. |
| Buffs | Seeded pickups honor map spawns and configured replacement delay. Fixed team and duration handling, carrier offset and tint, Swapper motion and credit, Disability speed scaling on affected projectile paths and bot aim. Restored the separate Magnet settings from upstream. | Dynamic lighting, filtering and Swapper edge cases. The unused upstream particle helper did not justify adding an effect. |
| Map selection | One parser feeds Create Game, hosted rotation and the map listing. It handles aliases, generated sidecars and current mode settings, including Mayhem, Team Mayhem, Team Keepaway and Survival. Tests cover chained promotions and explicit declarations. | Map generation from BSP contents and per-mode mapinfo defaults. Large deathmatch arenas still expose a product choice between the existing catalog and detail policies. |
| Items Guide | The native Guide now lists 14 item entries with pickup quantities, capacity and compatible weapons. All 18 numeric defaults checked against the pinned balance file matched. The running menu displayed the list and Bullets description. [Native capture](review/guide.webp) | The new descriptions need translation entries. Six other Guide topics still lack an entry source. |
| Crylink projectiles | Short-profile spikes fade their body, light and trail via the existing snapshot alpha field. Regression cases cover intermediate alpha, the hidden sentinel, codec round trips and unrelated projectiles. The stock five-second fade at 64 Hz exceeds the original 255-tick field and correctly remains opaque. | Clients sample the envelope at snapshot cadence. A fade shorter than the snapshot interval can go unseen. Existing particles in the modern GPU trail approximate the upstream ramp. |
| Grenade orbs and vehicle HUD | The orb uses the original shield mesh, skin, additive material, radius curve, fade and spin. Overlap applies the first matching flash. Vehicle aim indicators now select the original hint and lock assets. | The wire carries expiry without original lifetime. A client first observing an existing orb estimates its age. Moving effects and remote HUD rendering need paired capture. |

Several old findings changed classification. Native map voting already suppresses the scoreboard and follows the documented native UI decision. An interactive scoreboard and a Porto preview already exist, with residual behavior still to verify. The four config changes for texture compression, hostname and the two player limits have explicit native settings. The registry retains the evidence behind those decisions.

High-impact areas still in the inventory include render-rate movement for effects, XonStat profile and skill data, Onslaught objective presentation, map eligibility flags and mapinfo generation. The native profile dialog requests a statistics update and the match path builds a report, but the original data service workflow remains incomplete. These leads differ in scope and some span several rows.

## Collision measured against original maps

The shared-library experiment replayed 4,800 traces recorded from DarkPlaces across eight trace sets. On original geometry, native defaults matched exactly on 2,725, were within tolerance on 111 more and differed on 1,964. With the full compatibility settings, 4,751 matched exactly and the other 49 were within tolerance. The tolerance for end position is 0.01 game units. The test also checks solid flags.

On the rebuilt maps, the same test reached Stormkeep and failed its zero-difference assertion even with all compatibility settings enabled. Of 600 curved-surface traces there, 589 were exact, five were close and six differed. The largest difference was 144.031 game units. The original Stormkeep corpus passed with the same code. The comparison isolates an input-dependent difference. It does not identify a specific BSP lump as the cause. The decision page keeps the native movement policy separate from this measured map-rebuild discrepancy.

## Verification and council

- Debug and Release game builds succeeded. All 5,944 tests in the full .NET 8 suite passed with the project's 31 native map packs installed. Some tests return early without optional original binaries, so separate runs supplied the real recordings and original maps.
- Both original demos completed the legacy replay tests in null and headless host modes. Four cases passed. All 10,201 messages in Little Bot Orchestra and 35,605 in The Big Keybench decoded with zero VM faults or desyncs. Native menu playback of the original files remains an open product decision.
- A native Freeze Tag listen match on Stormkeep with buffs and two bots started, accepted the connection and loaded the bot waypoints. That smoke run did not exercise every freeze, revive or buff transition.
- Firefox verified all seven choices, changing and clearing answers, downloaded prompt contents, omitted unanswered questions, image loading and mobile width. The game screenshots come from the running native game. Small reference previews on the artwork card display both actual atlases. The screenshots illustrate the UI and map context. The measured comparisons use the original files, tests and traces.
- One GPT-6.2 Astra reviewer and one GPT-6.2 Sol reviewer examined the changes. The council caught a dropped CTS lap restart, spawnpoint-triggered timing, a replacement buff delay, an uppercase gametype alias and an ambiguity between declared and promoted map modes. Regression checks cover the fixes. The final round also strengthened the source anchors, pinned config reads, map provenance and scope labels. Its remote reviewer shells could not open the checkout, so the final reviewers received the changed code inline and their findings were checked in the worktree.

The [reproduction instructions](README.md#evidence-for-a-completeness-review) describe the generators, input revisions and classifications. A complete claim about player-visible behavior still requires closing the source and runtime queues, including paired original/native sessions for remote clients and rendering.
