Status in Vortex Arena

This documents upstream Xonotic. The Godot/.NET port implements the local ban system in full — ban, kickban, unban, banlist, crypto-id bans, the 256-slot store and the g_banned_list serialization — but not the HTTP cross-server sync, which Bans.cs leaves out to keep that core Godot-free. Better banning support is coming to Vortex Arena soon; it is not implemented yet.

Sections 01–07 apply to a stock Xonotic dedicated server. Section 08 covers what carries over today.

01 How ban syncing works

Every Xonotic server already keeps its own ban list locally, in a cvar named g_banned_list. That needs no configuration: sv_cmd kickban writes to it and banned players are dropped when they connect.

Ban syncing is an optional layer on top. Once enabled, a server does two things over HTTP. It reports each new ban to one or more provider URLs, and every few minutes it downloads bans placed by servers you have explicitly named as trusted. Imported bans are stored with a short expiry and renewed at each sync, so when the originating server lifts a ban it drains out of everyone else's list within roughly one sync interval.

What you provide

One HTTP host reachable by every game server. Xonotic ships no provider, and there is no public project-run list to join.

What Xonotic provides

The client half: reporting, polling, parsing, expiry handling and enforcement, all driven by the g_ban_sync_* cvars.

Before you enable it

Whoever runs the provider sees your server's hostname and every address you ban, and any server you list as trusted can push bans onto yours. Only sync with people you would already trust with rcon access.

02 Run a provider

You need one host that all your game servers can reach over HTTP. The provider is one Python file with no dependencies beyond the standard library, and keeps its state in a JSON file beside itself.

Source

The provider lives at github.com/VortexFPS/XonoticBanServer — with a systemd unit, an nginx TLS config, and tests. The full script is also reproduced below, so you can run it without cloning anything.

bansync.py — ban list provider (full source) 
#!/usr/bin/env python3
# SPDX-License-Identifier: GPL-3.0-or-later
"""A ban list provider for Xonotic dedicated servers.

Xonotic can share bans between servers over HTTP: each server reports the bans
it places to a "ban list provider", and periodically pulls back the bans placed
by the servers it trusts. Xonotic ships the client half; this is the provider.

Protocol (all GET, see qcsrc/server/ipban.qc upstream):

    ?action=ban&hostname=..&ip=..&duration=<seconds>&reason=..
    ?action=unban&hostname=..&ip=..
    ?action=list&hostname=..&servers=1.2.3.4;5.6.7.8

The reply to `list` is plain text, four LF-separated lines per ban:

    address           1-4 octets, an IPv6 prefix, or a 44-char crypto player id
    seconds remaining
    reason
    server            the IP of the game server that registered the ban

Xonotic discards a list reply that starts with "<", contains a carriage
return, or whose line count is not divisible by four.

No dependencies beyond the standard library. State lives in a single JSON file.

Usage:
    ./bansync.py --allow 192.0.2.10,192.0.2.11
    ./bansync.py --bind 127.0.0.1 --trusted-proxy 127.0.0.1   # behind nginx
"""

import argparse
import ipaddress
import json
import os
import sys
import threading
import time
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from urllib.parse import urlparse, parse_qs

MAX_REASON = 200


def normalize_ip(text):
    """Return a canonical form of an IP address, or None if it isn't one.

    Accepts the forms that turn up in proxy headers: bracketed IPv6
    (`[2001:db8::1]`), and IPv4 with a port (`192.0.2.10:54321`). An IPv6
    address with a port is only unambiguous in the bracketed form, so a bare
    colon-bearing string is tried as IPv6 first.
    """
    if not text:
        return None
    text = text.strip()
    if text.startswith("["):
        text = text.partition("]")[0][1:]
    else:
        try:
            return str(ipaddress.ip_address(text))
        except ValueError:
            pass
        if text.count(":") == 1:                      # IPv4:port
            text = text.rsplit(":", 1)[0]
    try:
        return str(ipaddress.ip_address(text))
    except ValueError:
        return None


class BanStore:
    """The ban list, persisted to JSON.

    Every read-modify-write goes through the lock. The server is threaded, so
    without it two servers banning at the same moment can lose one of the bans:
    both read the same list, both append, and the second write wins.
    """

    def __init__(self, path):
        self.path = path
        self.lock = threading.Lock()

    def _load(self):
        try:
            with open(self.path, encoding="utf-8") as fh:
                data = json.load(fh)
        except (OSError, ValueError):
            return []
        if not isinstance(data, list):
            return []
        now = time.time()
        return [b for b in data if isinstance(b, dict) and b.get("expires", 0) > now]

    def _save(self, bans):
        tmp = self.path + ".tmp"
        with open(tmp, "w", encoding="utf-8") as fh:
            json.dump(bans, fh, indent=1)
        os.replace(tmp, self.path)                     # atomic: readers never see a half-written file

    def add(self, ip, duration, reason, server):
        with self.lock:
            bans = self._load()
            bans = [b for b in bans if not (b["ip"] == ip and b["server"] == server)]
            bans.append({
                "ip": ip,
                "expires": time.time() + duration,
                "reason": reason,
                "server": server,
            })
            self._save(bans)

    def remove(self, ip, server):
        """Drop a ban. A server may only lift the bans it placed itself."""
        with self.lock:
            bans = self._load()
            kept = [b for b in bans if not (b["ip"] == ip and b["server"] == server)]
            removed = len(bans) - len(kept)
            if removed:
                self._save(kept)
            return removed

    def list_for(self, servers):
        with self.lock:
            bans = self._load()
        now = time.time()
        out = []
        for b in bans:
            if b["server"] not in servers:
                continue
            out += [
                b["ip"],
                str(int(b["expires"] - now)),
                b["reason"] or "no reason given",
                b["server"],
            ]
        return out


class Handler(BaseHTTPRequestHandler):
    server_version = "xonotic-bansync/1.0"

    # Injected by serve(); class attributes so every request handler sees them.
    store = None
    allowed_servers = frozenset()
    trusted_proxies = frozenset()

    # ---- helpers -------------------------------------------------------

    def origin_ip(self):
        """The game server that made this request.

        Directly connected: the peer address. Behind a reverse proxy the peer
        is the proxy, so walk X-Forwarded-For from the right and return the
        first hop that is not itself a trusted proxy. Only headers arriving
        from a configured proxy are honoured — otherwise any client could name
        its own address and impersonate a trusted server.
        """
        peer = normalize_ip(self.client_address[0]) or self.client_address[0]
        if peer not in self.trusted_proxies:
            return peer
        forwarded = self.headers.get("X-Forwarded-For", "")
        for hop in reversed([h for h in forwarded.split(",") if h.strip()]):
            candidate = normalize_ip(hop)
            if candidate and candidate not in self.trusted_proxies:
                return candidate
        return peer

    def reply(self, body, status=200):
        raw = body.encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(raw)))
        self.end_headers()
        self.wfile.write(raw)

    def may_write(self, origin):
        return not self.allowed_servers or origin in self.allowed_servers

    # ---- request handling ----------------------------------------------

    def do_GET(self):
        query = parse_qs(urlparse(self.path).query)
        action = query.get("action", [""])[0]
        origin = self.origin_ip()

        if action == "ban":
            if not self.may_write(origin):
                self.log_message("REFUSED ban from %s (not in allowlist)", origin)
                return self.reply("forbidden\n", 403)
            ip = clean(query.get("ip", [""])[0])
            reason = clean(query.get("reason", [""])[0])
            try:
                duration = float(query.get("duration", ["0"])[0] or 0)
            except ValueError:
                duration = 0
            if ip and duration > 0:
                self.store.add(ip, duration, reason, origin)
                self.log_message("ban %s by %s for %ds (%s)", ip, origin, int(duration), reason)
            return self.reply("ok\n")

        if action == "unban":
            if not self.may_write(origin):
                self.log_message("REFUSED unban from %s (not in allowlist)", origin)
                return self.reply("forbidden\n", 403)
            ip = clean(query.get("ip", [""])[0])
            if ip and self.store.remove(ip, origin):
                self.log_message("unban %s by %s", ip, origin)
            return self.reply("ok\n")

        if action == "list":
            wanted = {s for s in query.get("servers", [""])[0].split(";") if s}
            lines = self.store.list_for(wanted)
            return self.reply("\n".join(lines) + ("\n" if lines else ""))

        # Anything else: an empty body. Never HTML — Xonotic rejects a list
        # reply that starts with "<" as an error page.
        return self.reply("")

    def log_message(self, fmt, *args):
        print("%s %s" % (self.log_date_time_string(), fmt % args), flush=True)


def clean(text):
    """Strip what would corrupt the four-lines-per-ban reply format."""
    return text.replace("\r", " ").replace("\n", " ").strip()[:MAX_REASON]


def parse_ip_set(values, label):
    result = set()
    for chunk in values:
        for item in chunk.split(","):
            item = item.strip()
            if not item:
                continue
            address = normalize_ip(item)
            if address is None:
                sys.exit("%s: %r is not an IP address" % (label, item))
            result.add(address)
    return frozenset(result)


def serve(bind, port, store_path, allowed, proxies):
    Handler.store = BanStore(store_path)
    Handler.allowed_servers = allowed
    Handler.trusted_proxies = proxies

    if not allowed:
        print("WARNING: no --allow given; any host that can reach this port "
              "may place bans", flush=True)
    print("bansync listening on %s:%d, store=%s, allowed=%s, proxies=%s"
          % (bind, port, store_path,
             ",".join(sorted(allowed)) or "(any)",
             ",".join(sorted(proxies)) or "(none)"), flush=True)

    ThreadingHTTPServer((bind, port), Handler).serve_forever()


def main(argv=None):
    parser = argparse.ArgumentParser(description="Xonotic ban list provider")
    parser.add_argument("--bind", default=os.environ.get("BANSYNC_BIND", "0.0.0.0"),
                        help="address to listen on (default: 0.0.0.0)")
    parser.add_argument("--port", type=int, default=int(os.environ.get("BANSYNC_PORT", 8080)),
                        help="port to listen on (default: 8080)")
    parser.add_argument("--store", default=os.environ.get("BANSYNC_STORE", "bans.json"),
                        help="path to the JSON ban store (default: bans.json)")
    parser.add_argument("--allow", action="append", default=[],
                        help="game server IP allowed to place bans; repeatable "
                             "or comma-separated. Omit to allow any host.")
    parser.add_argument("--trusted-proxy", action="append", default=[],
                        help="reverse proxy IP whose X-Forwarded-For header is "
                             "honoured; repeatable or comma-separated")
    args = parser.parse_args(argv)

    if not args.allow and os.environ.get("BANSYNC_ALLOW"):
        args.allow = [os.environ["BANSYNC_ALLOW"]]
    if not args.trusted_proxy and os.environ.get("BANSYNC_TRUSTED_PROXIES"):
        args.trusted_proxy = [os.environ["BANSYNC_TRUSTED_PROXIES"]]

    serve(
        args.bind,
        args.port,
        args.store,
        parse_ip_set(args.allow, "--allow"),
        parse_ip_set(args.trusted_proxy, "--trusted-proxy"),
    )


if __name__ == "__main__":
    try:
        main()
    except KeyboardInterrupt:
        pass
Start it
python3 bansync.py --allow 192.0.2.10,192.0.2.11

It listens on port 8080. --allow lists the game servers permitted to place bans; everything else gets a 403. Reading the list stays open, since that is what the servers poll. Omit the flag and any host that can reach the port may ban — the provider warns about this at startup.

Put it behind TLS

The requests carry banned players' IP addresses in the query string, so terminate TLS if the provider is reachable from the internet. The repository ships bansync.service and nginx.conf.example for exactly this.

python3 bansync.py --bind 127.0.0.1 --trusted-proxy 127.0.0.1 --allow 192.0.2.10
Proxies need this flag

Bans are keyed by the IP that placed them, and servers pull by that key. Behind a proxy every request appears to come from the proxy, so without --trusted-proxy every ban is filed under 127.0.0.1 and the sync returns nothing. With it, the real address is read from X-Forwarded-For — and only when the connection came from a configured proxy, so nobody else can claim to be a trusted server.

Check it answers

With no bans recorded yet this returns an empty body, which is the correct response:

curl "http://bans.example.net:8080/?action=list&hostname=test&servers=192.0.2.10"

The repository's test suite covers the wire format, the allowlist, proxy attribution and concurrent writes:

python3 -m unittest -v

03 Configure each game server

Add this to ~/.xonotic/data/server.cfg on every server in the group, substituting your own provider address and the public IP addresses of the other servers.

// where bans are reported to, and fetched from
set g_ban_sync_uri "http://bans.example.net:8080/"

// whose bans this server accepts — NOT this server's own IP
set g_ban_sync_trusted_servers "192.0.2.10 192.0.2.11"

// how often to pull, in minutes
set g_ban_sync_interval 5

Each server needs its own g_ban_sync_trusted_servers listing the others, never itself:

Serverg_ban_sync_trusted_servers
192.0.2.10"192.0.2.11 192.0.2.12"
192.0.2.11"192.0.2.10 192.0.2.12"
192.0.2.12"192.0.2.10 192.0.2.11"
Never trust yourself

A server that lists its own IP re-imports every ban it lifts on the very next sync, and unbanning silently stops working.

Leaving g_ban_sync_trusted_servers empty is valid and means "push only" — the server reports its bans but imports none. That is a reasonable setting for a server whose admin you trust less than the rest of the group.

Optional hardening

set g_ban_sync_trusted_servers_verify 1   // discard bans attributed to servers you didn't ask for
set g_ban_sync_timeout 45                 // seconds before a sync request is written off

g_ban_sync_uri accepts up to 16 space-separated URLs if you want to report to more than one provider.

04 Place a ban that will actually sync

A ban with no reason is never reported to the provider. It is stored locally and silently skipped by the sync. A reason beginning with ~ is skipped too — that prefix marks a ban placed by an unauthenticated admin. So always pass a reason:

sv_cmd kickban 3 86400 3 aimbot

client #3 · 86400 seconds · mask size 3 · reason "aimbot"

CommandWhat it does
sv_cmd kickban <client> [bantime] [masksize] [reason]Drops a connected player and bans them.
sv_cmd ban <address> [bantime] [reason]Bans an address or player ID that is not connected right now.
sv_cmd banlistLists active bans with the index number unban needs.
sv_cmd unban <banid>Lifts ban number banid, and tells the provider to drop it.
sv_cmd whoShows connected players with their IP and cryptographic ID.

masksize sets how wide the net is:

masksizeIPv4IPv6Use it when
1/8/32Never, in practice — it bans millions of addresses.
2/16/48A hostile network range, accepting heavy collateral.
3/24/56Default. Survives most consumer IP churn.
4/32/64One address only, no collateral.

Banning a player ID

Cryptographic player IDs sync exactly like addresses. An ID is the 44-character fingerprint a signed player key presents on connect; unlike an address it survives a reconnect from somewhere else, which makes it the better tool against a returning cheater. Read it from the crypto_id column of sv_cmd who, then ban it wherever an address would go:

sv_cmd ban Xt3q…44-characters…kP= 604800 aimbot

sv_cmd kickban on a connected player who has a key records both the address ban and the ID ban automatically, so this is only needed for someone who has already left.

Documented but not implemented

g_ban_default_masksize 0 is described as "ban by UID only", but neither the QuakeC nor the C# port has a branch for 0 — both fall through to banning the single full IP. For an ID-only ban, place it explicitly with sv_cmd ban <id>.

05 Verify the sync

Ban someone on one server, then check each link in the chain.

The provider recorded it

Its log prints a line naming the banning server:

ban 203.0.113.0 by 192.0.2.10 for 86400s (aimbot)
The list endpoint returns it

Query it the way another server would. Four lines per ban, always in this order:

curl "http://bans.example.net:8080/?action=list&hostname=test&servers=192.0.2.10"
203.0.113.0    ← address
86321          ← seconds remaining
aimbot         ← reason
192.0.2.10     ← server that registered it
The other servers imported it

Their consoles print this once per interval:

Received ban list from http://bans.example.net:8080/: OK, 1 items
Ban list syncing: accepted ban of 203.0.113.0 by 192.0.2.10 at http://…: aimbot

Failures name themselves in the same place:

A server holds 256 bans in total, local and synced together. Past that a new ban only lands if it outlasts the entry it would replace.

07 Protocol, for writing your own provider

Three GET requests. All values are URL-encoded; hostname is the reporting server's name.

?action=ban&hostname=..&ip=..&duration=<seconds>&reason=..
?action=unban&hostname=..&ip=..
?action=list&hostname=..&servers=1.2.3.4;5.6.7.8;..

The reply to list must satisfy all of the following, or the server discards it:

  • Plain text, four lines per ban — address, seconds remaining, reason, and the IP of the server that registered it.
  • Separated by bare line feeds. A single carriage return anywhere voids the whole response.
  • Must not begin with <, which is how an HTML error page is detected.
  • Total line count divisible by four.
  • An address is 1–4 dot-separated octets, an IPv6 prefix, or a 44-character player ID.

An IP given as fewer than four octets is a network mask: 203.0.113 covers the whole /24.

08 What the Vortex Arena port carries over

The Godot/.NET port reimplements the local half faithfully and leaves the HTTP half out for now. Better banning support is planned and coming soon — none of it has landed yet, so treat the table below as the current state, not the destination.

FeatureStatusNotes
Local ban store, 256 slotsyesSame version-1 g_banned_list string, storing time remaining.
ban / kickban / unban / banlistyesSame argument order; unban uses the index banlist prints.
Crypto-id bansyesAn ID match always bans; an IP match respects g_banned_list_idmode.
who with the crypto_id columnyesHonours sv_status_privacy.
mute / playban listsyesg_chatban_list, g_playban_list, g_voteban_list — ID prefixes accepted.

Expanded banning toolssoonBetter banning support is on the roadmap; nothing has shipped yet.

To share bans between Vortex Arena servers today, distribute g_banned_list out of band — generate the config from one source and deploy it to each server.
