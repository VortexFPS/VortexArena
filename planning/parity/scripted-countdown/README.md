# Scripted kill countdown

The recorder runs a dedicated loopback server and two graphical clients. BlueProbe joins Deathmatch, teleports to the clone marker, takes one standing copy with impulse 142, and teleports away to the player marker. RedProbe observes both positions from `-288 -208 112`, yaw 0°, pitch 11°. BlueProbe then presses a bound `kill` key. The server uses a four-second delay, zero anti-spam extension, and a two-clone allowance. Both arms use the same Running Man CTF fixture BSP and original external lightmaps. The original Xonotic data is pinned to `863cd3e8456e18f577f7fe5fef857ff55ae62cc0`.

Run these commands sequentially with fresh output directories. The observer uses the named display and the player uses the next one. The recorder uses two llvmpipe threads per engine process and a 30 Hz server tick in both arms. It uses 640 × 480 for the original and 480 × 360 for the native capture. The native server also needs a free adjacent port for LAN discovery.

```sh
python3 planning/parity/scripted-countdown/record.py --engine original --port 26910 --display 171 --output /tmp/new-countdown-original
python3 planning/parity/scripted-countdown/record.py --engine native --port 26911 --display 173 --output /tmp/new-countdown-native
```

The original observer capture shows two standing bodies before the command, two copies of each digit from 4 through 1, and the cleared lane after expiry. The original server recorded a single suicide for BlueProbe. The frame manifest records the selected images and their sample time in the action timeline. [Original frames](original/frames.json) · [Original server log](original/server.txt) · [Original timeline](original/timeline.jsonl)

The earlier attempts in `/tmp/va-countdown-*` retain their command lines and process logs. Several stopped during graphical sign-on or timed out waiting for a self-join message that the original client does not reliably print. The recorder now uses the dedicated server log for original sign-on. Software rendering and screenshot sampling use wall time, so the captures do not measure the 50 ms per-clone stagger. Audio was disabled for this comparison. One original repeat showed the player digits and both bodies at expiry, but its observer frames did not resolve the clone’s digits. The recorder disables original server entity culling in the isolated fixture. The final original run captured both sets of digits. [Reduced-resolution original repeat](original-480-repeat/frames.json)

The initial completed native run recorded BlueProbe’s first-person “Suicide in 4” and obituary and logged one suicide. Its observer lane showed only the active player in the sampled pre-kill frames. That run had major rendering stalls and used the bare impulse command. A second native attempt used the explicit server command and logged the suicide, but first-person captures reached the teleport markers several seconds after the action timeline. The recorder now allows the graphical clients time to catch up between actions and waits for the server’s suicide event before ending the capture. [Native baseline frames](native-baseline/frames.json) · [Native baseline server log](native-baseline/server.txt)

A diagnostic run confirmed that the native server created the clone at the intended origin and assigned 4, 3, 2, and 1. The player client received the clone’s full state. The observer received the digit deltas with an empty model and, for the clone, a zero origin. On a slow client, a new snapshot can reuse the ring slot for its acknowledged baseline. The native decoder now reconstructs the new snapshot before recycling that slot. The regression test covers a digit-only delta and a truncated retry at the same sequence. [Diagnostic server log](diagnostic/server.txt) · [Observer log](diagnostic/RedProbe.txt) · [Player log](diagnostic/BlueProbe.txt)

The first repeat with the snapshot fix rendered both bodies again. It exposed two remaining presentation differences. The native sprite loader supplied a view-oriented sprite through the DarkPlaces asset path, so the digit quad needed the observer’s view-plane transform. A gibbed body also stayed in the snapshot until its cleanup think, and the compatibility renderer continued drawing it. The sprite now uses the view-plane transform for its offset and scale, and snapshots omit gibbed body copies immediately. [Snapshot repeat frames](native-snapshot-fix/frames.json)

The fixed native capture shows overhead 4, 3, 2, and 1 on both the player and the clone, the player’s first-person countdown, and the clone’s disappearance. The observer’s nameplates are disabled so they leave both digits visible. The player’s corpse and dropped weapon remain visible after expiry. The server logged exactly one suicide. The native and original captures share their BSP and external lightmaps, and use their respective materials and player colors. [Native frames](native/frames.json) · [Native server log](native/server.txt) · [Native timeline](native/timeline.jsonl)
